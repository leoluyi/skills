# Layer: Color — 顏色層

角色 → 色值。每個角色該用什麼填色、邊框、文字色。

角色定義在 `roles.md`；具體數值在 `../themes/`；本檔是**推導規則**——
主題只填 base，其餘全部算出來。

## 分工

| | 內容 | 在哪 |
|---|---|---|
| 主題 | 每個類別一個 base hex，加 canvas、ink、terminal、accent | `../themes/*.md` |
| 本檔 | 由 base 推導其餘六階的公式與約束 | 這裡 |

主題刻意只有 8 個值。多一個值，就少一組主題會被做出來。

## 類別角色

`cat-1` … `cat-N` 用於階段、泳道、層級、參與方等**平行類別**。
刻意不叫 `phase`，因為同一組色在不同圖可能編碼不同維度。

**編號本身沒有語意。** `cat-1` 在這張圖是「接收階段」，在另一張可能是「使用者」。
跨圖固定的只有兩件事：

1. **在單張圖內獨佔。** 一旦指派，該色不得再出現在別處——類別色是承諾。
2. **明度隨編號遞增。** `cat-1` 最暗、`cat-N` 最亮。

第二點是慣例，`derive.py` 只回報不強制——**並列類別**（泳道、參與方、層級）
沒有閱讀順序要遷就，非遞增完全合理。**色相順序與明度順序可以各自決定。** 想把某個色相排在特定位置，
調它的明度即可——`spectral-ramp` 的靛紫原本明度 8，
提亮到 78 之後仍是紫，但排得進末位而不破壞遞增。但**有序類別**（階段、步驟）非遞增時，
明暗會與閱讀順序反向，第二階看起來比第三階「輕」。
選主題前先看那行 `category lightness`。

> 

單值角色：`canvas`、`ink-strong`、`ink-muted`、`connector`、`infra`、`terminal`、`accent`。
`accent` 限 3 處以內，且不可與任何 `cat-*` 同色。

以 `mix(base, canvas, p)`：`channel = base_ch × p + canvas_ch × (1 − p)`

**混的對象是 canvas，不是白色。** 深底主題的卡片必須比底色亮一階而非暗一階，
寫死白色會讓深底主題整組壞掉。

| 衍生 token | p | 用途 |
|---|---|---|
| `--cat-N-region` | 4% | 帶狀區域底（region） |
| `--cat-N-region-line` | 16% | 區域外框 |
| `--cat-N-card` | 10% | 卡片底（card） |
| `--cat-N-card-sub` | 16% | 巢狀子卡片底 |
| `--cat-N-base` | 100% | **僅作主題輸入值，不直接畫任何東西** |
| `--cat-N-line` | 解對比方程（對 `card` 3.2:1） | 卡片邊框、色條、徽章底、圖示 |
| `--cat-N-badge-ink` | 白或畫布色，取對比高者 | 徽章上的文字 |
| `--cat-N-label` | 解對比方程（對 `region` 4.6:1） | 區域標題文字 |

**`line` 與 `label` 不同值。** `label` 是文字，對 `region` 解到 4.6:1；
`line` 是邊框，圖形元素只需對 `card` 達 3:1（實取 3.2）。

兩者曾經共用 4.6，等於用文字的標準要求邊框——飽和琥珀被壓成焦橘，
不再像它出身的顏色。拆開後邊框留在 base 附近，標題仍夠深。
固定明度在藍色會過關、在黃色會悄悄不及格——等明度不等於等對比。

**墨色的解算方向隨畫布明暗翻轉。** 淺底時 `line` 從 base 往**黑**解，
深底時往**白**解——深底還往黑走只會讓對比更差，解到全黑仍然不及格。

**徽章文字不能寫死白色。** `line` 在深底上是亮的，白字壓上去會塌掉。
`badge-ink` 在白與畫布色之間取對比高者，`terminal` 上的文字同理。

**色票看起來太淡時，先分清是彩度還是明度。** 兩者都會讓色票讀成空白，
但解法相反：彩度不足要提彩，明度太高要**重排整條階梯**把它降下來——
而降一個就得連帶下移其他階，否則間距不夠。
`spectral-ramp` 的 cat-4 就是後者：從明度 78 降到 62 才恢復可辨。

**base 的飽和度會傳給邊框。** `line` 是從 base 壓暗解出來的，色相與飽和度都繼承。
所以一個高飽和的 base 即使卡片很淡，邊框仍會很跳——
`spectral-ramp` 的 cat-4 就是為此把 base 壓到 S38。
**調某個類別的存在感，調它的 base 飽和度，不要去改邊框。**

**base 本身不畫任何東西。** 飽和中間調對自己的 10% 淡底通常只有 2–3:1，
拿來當邊框達不到 WCAG 對圖形元素的 3:1。但把門檻加在 base 上會讓它必須夠暗
（相對亮度 ≤26%），而灰階規則又要求四個類別散開 30 點——兩條同時成立時
最多只放得下兩個類別。解法是讓 base 只負責色相，把「必須看得見」的工作
全部交給解過對比的 `line`：邊框、色條、徽章底、圖示共用同一個值。

**灰階可分性**：任兩個類別 base 的相對亮度差需 ≥10%。
低於這個值，圖列印成黑白後兩類就糊在一起，而顏色本來就不該單獨承載意義。
低飽和主題最容易踩——柔和調性本質上壓縮明度範圍，
被擋下時拉開明度階梯，不要靠加徽章硬過。

**暖色修正**：黃／橙／紅色相在同一 p 值下感知偏淡。
`cat` base 若落在 hue 20°–60°，各階 p 值 **+6～8 個百分點**，
否則區域底會淡到看不見。冷色不需修正。

**驗證**：`python scripts/derive.py themes/<theme>.md` 會算出全部衍生值並實測對比。
不要手算，也不要憑印象判斷——暖色尤其騙眼睛。

## 現成框架色系的通病

Bootstrap、Tailwind、Solarized 的預設色**沒有一組通得過灰階閘門**。
這不是三次巧合，是同一個設計目標的必然結果：它們為螢幕 UI 調色，
那裡顏色永遠在，換色時只希望**視覺重量不變**。

| 色系 | 病徵 | 實測 |
|---|---|---|
| Bootstrap | `primary` 與 `success` 明度**完全相同** | 都是 18% |
| Tailwind | 色階依感知明度均勻切分，同階跨色相必然相近 | emerald-500 36、amber-500 44 |
| Solarized | 官方明講強調色齊平（L\*55–60） | 八色全擠在 17–28 |

**Bootstrap 那個最難救**：藍與綠在每一階都同亮度（shade 20% 後 11.3 對 11.3、
shade 40% 後 6.2 對 6.2），兩條線平行下降，同步加深永遠不會分開。
唯一的解是**取不同階**。

通則：**跨色相時要換階，不要固定在同一階。** 取用任何現成色系前先跑
`derive.py` 實測，不要假設「知名色系應該沒問題」。

## 加新主題

使用者給一張色票時，走 `adding-a-theme.md` 的七步流程。
那份文件把這裡的原理翻成可執行的步驟，含可直接貼上的量測腳本。

**最常見的錯誤是直接照抄色票。** 多數現成色票是連續漸層或 UI 色系，
相鄰色的明度差不到 10，整條拿來當類別色會被灰階閘門擋下——必須跳著取。

## 濃度模式

預設階梯（region 4%／card 10%／card-sub 16%）是為**低飽和主題**調的。
飽和色票套上去會只剩邊框帶顏色，卡片本身是一層洗白——色票的特色被抹掉。

對比其實有很大餘裕：`ink` 對 45% 的濃底仍有 7:1。所以飽和主題該把表面推上去。

| | 預設 | `vivid: true` | `print: true` |
|---|---|---|---|
| `region` | 4% | **14%** | 8% |
| `card` | 10% | **38%** | 14% |
| `card-sub` | 16% | **50%** | 22% |
| `region-line` | 16% | **40%** | 22% |

38% 是實測比較 10／26／38 三檔後選的：10% 只有邊框帶顏色，26% 好轉，
38% 才真的還原色票性格，而 `ink` 對 45% 的濃底仍有 7:1，所以還有餘裕。

**卡片有明度下限 78%（子卡片 70%）。** 固定的混色比例不等於固定的結果——
38% 套在很暗的 base 上會落到明度 50，那樣的卡片重到讓深色文字讀起來像反白，
即使對比比值仍然合格。碰到下限時自動退回混色比例，直到卡片夠淺為止。

下限訂在 78 是因為其他主題的卡片本來就落在 79–91；訂低於此，
同一份文件裡不同主題的卡片會明顯不等重。

實例：`spectral-ramp` 的 cat-1 `#54478C`（明度 6.6）原本得到明度 50 的卡片，
退回混色比例後回到 78。淺色 base 的主題完全不受影響。

**每組主題都必須明確宣告 `mode:`**，沒有隱含預設。四個值：

| `mode:` | 效果 |
|---|---|
| `standard` | 預設階梯 |
| `vivid` | 表面濃度提高，給飽和色票 |
| `print` | 網點下限 8%、灰階門檻 15%、畫布須純白 |
| `outline` | 表面不填色，類別上限 3 |

**`print vivid` 可以並存。** vivid 的每一階都高於 print 的下限
（14>8、38>14、50>22、40>22），所以 vivid 的階梯本身就滿足網點需求；
print 另外兩條規則（純白畫布、灰階門檻 15%）與濃度無關。
兩者同時宣告時走 vivid 的階梯、套 print 的其餘規則。

（這兩者一度被設成互斥，理由是「目的相反」。那是錯的——
目的相反不表示規則衝突，實際比對階梯就會發現它們相容。）

## 列印模式

主題檔含 `print: true`（或帶 `--print`）時，三件事同時改變：

| | 螢幕 | 列印 | 為什麼 |
|---|---|---|---|
| 網點下限 | 4% | **8%** | 平版與雷射印不出 8% 以下，會掉字或斑駁 |
| 灰階間距門檻 | 10% | **15%** | 影印比灰階渲染粗暴，10% 二次影印後會糊 |
| 畫布 | 任意 | **必須 `#FFFFFF`** | 印近白底費墨，且圖與頁面交界會出現方框 |

網點上移的代價是階與階變近，卡片與區域底的區別在螢幕上會弱一些。
這是為紙面付的錢，不要在螢幕上「修回來」——改回去紙上就掉字了。

## 執行

```bash
python scripts/derive.py themes/<theme>.md
```

輸出可直接使用的色值表與對比報告。**exit 0 才能繼續。**
擋下的三類問題：文字對比不足、類別色被誤用來寫字、灰階不可分。

## 樣式參考表

`docs/style-reference.html` 是整套系統的單一參考表：角色語意、三種筆調、
四種狀態、五種線型、各主題的實際推導值。每組顏色**畫在自己的畫布色上**——
色階是相對畫布推導的，全部排在白底會失真。

```bash
python scripts/render_reference.py       # 重生 docs/style-reference.html
```

所有數值都是當場從 `pens/*.md` 與 `themes/*.md` 讀出、經 `derive.py` 推導的，
不會與實際值脫節。**改過任何主題或筆調就重跑**——過期的參考表比沒有更糟，
因為它看起來是權威的。

做成 HTML 而非圖片，是為了三件圖片做不到的事：hex **點擊即複製**，
那是打開色票表的主要目的；CJK 用讀者自己的字型，不必賭匯出機器裝了什麼；
以及**灰階可以真的切換**。

最後一項也是為什麼筆調與狀態跟顏色放在同一頁而非各自一張圖：
三者做的是同一個承諾——**掉成黑白後仍讀得懂**——一個切換鍵可以同時檢驗全部。
分成兩份的話，其中一份被重生而另一份沒有時就會開始漂移。

用瀏覽器開啟即可，無外部相依。

## 回歸測試

```bash
python scripts/test_themes.py            # 比對基準
python scripts/test_themes.py --update   # 改動後重建基準（務必檢查 diff）
```

`tests/fixtures/` 存放五組主題與七個閘門案例的完整輸出。
色彩的錯誤特別容易靜默——解析器改一行可能讓某個模式旗標讀不到，
訊息改一句可能蓋掉是哪道閘門觸發，兩者都要等到有人畫圖瞇著眼看才會發現。

閘門案例鎖的是**規則本身**而非任何主題：五類別在填色模式該被擋、
四類別在純框線模式該被擋、深底時墨色該往亮處解。這些路徑沒有主題檔守著。

**改完 `derive.py` 一定跑一次。** 這組基準建立當天就抓到深色畫布的墨色解算方向是反的。
