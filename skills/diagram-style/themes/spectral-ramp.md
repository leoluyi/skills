# Spectral Ramp — 光譜階（4 類別）

青 → 薄荷 → 黃綠 → 淡紫。取自一組十色的紫—藍—青—綠—黃—橘連續漸層。

**適用**：**類別數 4** 的有序流程與並列類別皆可。
明度 21 / 53 / 63 / 78 遞增，色相涵蓋青綠黃紫。

與 `dusk-ramp`（7/27/46/61）的差別：這組整體偏亮、飽和度高、色相跨得遠，
適合螢幕；`dusk-ramp` 起點深、暖冷有明確方向，適合印出來看。

**不適用**：正式文件與列印（飽和度高、改用 `muted-ledger`）；
純框線筆調（上限 3）；類別之間沒有先後關係時。

```
mode: vivid
```

## 來源與取捨

原色票十色：`54478C` `2C699A` `048BA8` `0DB39E` `16DB93` `83E377`
`B9E769` `EFEA5A` `F1C453` `F29E4C`。

**十色裡只有四個進得來，但擋住的不是明度而是色相。**

明度上五個放得下（8／21／35／53／68 全部間距 ≥10）。
但 `0DB39E` 翡翠 (H172) 與 `16DB93` 薄荷 (H158) 只差 14°，
與 cat-2 青 `048BA8` (H190) 也只差 18°——三個擠在青綠家族裡。
彩色閱讀時它們是同一個色，灰階閘門卻看不見這件事。

**留薄荷不留翡翠**：留薄荷時色相最小差 33°，留翡翠只有 18°。

取第 3、5、7 色，加上第 1 色的**色相**——靛紫排在末位而非最前。

原色票的 `54478C` 明度只有 8，直接放末位會讓序列變成 21/53/68/8，
非遞增，明暗與閱讀順序打架。所以**保留它的色相 H251、提亮至最淺**，成為 `#D0CBEB` 淡紫。

明度停在 **62 而非更高**：紫色相在 70 以上必然接近白，
色票上會讀成一格空白。62 是「仍是紫、卡片仍淡」的交界。
為了讓它排在末位又保持 ≥10 間距，前三階一起下移——
薄荷 53→33、黃綠 64→49。**整條階梯重排，不是只動一個。**

**色相順序與明度順序是兩個獨立的選擇。** 想要某個色相排在特定位置時，
調它的明度即可，不必接受漸層原本的明暗次序。第五個進不來的理由同上：
`83E377` (61) 與 `B9E769` (68) 只差 7.4 明度，`EFEA5A` (78) 也只差 9.4。

尾端的 `F1C453` (59) 與 `F29E4C` (44) 明度反而下降——
那是漸層在暖端回落，不是取樣錯誤。`F29E4C` 因此拿去當 `accent`。

## 陷阱

五個類別已達 `derive.py` 的軟性提醒門檻。**再多一階就該問**，
那個區別讀者是不是真的需要——上限不是明度用完，是讀者記不住。

`#B9E769` 黃綠對自己的卡片底只有 1.3:1，是全部主題裡最低的，
**只能當邊框，寫在上面的字一定不合格**。薄荷 1.6:1、翡翠 2.4:1 同理。
只有靛紫可以直接寫字。

`highlight` 用 `#D6CD26` 而非原色票的黃：黃色相在同明度下對白紙特別淡，
釘在灰階 62% 時只有 1.40:1 過不了，壓到 58% 才達 1.66:1。
