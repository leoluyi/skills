# Roles — 語意角色

樣式不直接掛在圖元上，掛在**角色**上。「主標題」是角色，「28px 粗體深藍」是某個
preset 對這個角色的實作。換 preset 換的是實作，角色不動。

這一層的存在理由是**跨媒材**：SVG 的 `<rect>` 與 PPTX 的 `ROUNDED_RECTANGLE`
是同一個角色的兩種畫法。角色是契約，媒材是實作。

三組角色，筆調層與顏色層各自提供對應值。

---

## 文字角色

| 角色 | 用途 | 筆調層給 | 顏色層給 |
|---|---|---|---|
| `text/title` | 圖或投影片主標題，全圖唯一 | 字級、字重、行高 | `ink-strong` 或 `accent` |
| `text/section` | 區塊、階段、章節標題 | 字級、字重 | `cat-N-label` |
| `text/body` | 節點標籤、主要內容 | 字級、字重、對齊 | `ink-strong` |
| `text/support` | 子標、補充說明 | 字級、透明度 | `ink-strong` @ 62% |
| `text/caption` | 註記、來源、頁碼 | 字級 | `ink-muted` |
| `text/kicker` | 眉標、分類標籤 | 字級、字距 | `ink-muted` |
| `text/emphasis` | 單點強調，**≤3 處** | 字重 | `accent` |
| `text/inverse` | 深底上的文字 | 同 `text/body` | `#FFFFFF` |
| `text/highlight` | 螢光筆畫記，**≤2 處** | 底線式色塊，非整行反白 | `highlight` |

投影片可以使用顏色層提供的 `--slide-ink`、`--slide-emphasis`、`--slide-title-rule`、`--slide-hero` 與 `--slide-category-N` 語意別名。
完整映射與限制見 `layer-color.md` 的「投影片語意色」。

**CJK 不做 ALL-CAPS 也不加字距。** 大寫轉換對漢字無效，字距會破壞行氣。
英文眉標在中文語境維持原樣即可。

`text/support` 用透明度而非另一個色，是為了讓它自動跟著底色走——
換主題時不必重新解一次對比。

## 表面角色

**一個表面只有一個意思。** 這是整份文件最容易被違反、後果最貴的規則：
註解畫成物件，讀者會把說明讀成機制的一部分，圖裡憑空多出一個不存在的元件。

| 角色 | 意義 | 筆調層給 | 顏色層給 |
|---|---|---|---|
| `surface/object` | **一個東西**：元件、動作、角色 | `rx`、`stroke-width`、`fill` | `cat-N-card` + `cat-N-line` |
| `surface/part` | 巢狀子物件，從屬於某個 object | `rx − 2`、線細一階 | `cat-N-card-sub` |
| `surface/region` | **一個範圍**：階段、泳道、層 | `rx + 2`、色條寬 | `cat-N-region` + `region-line` |
| `surface/annotation` | **對圖的說明**，不是機制的一部分 | 點線框、無填色 | `ink-muted` @ 70% |
| `surface/infra` | 貫穿層、共用設施 | 全寬橫條 | `infra-card` + `infra-base` |
| `surface/terminal` | 終點，**全圖唯一** | 實心 | `terminal` + `text/inverse` |
| `surface/datasource` | 資料源 | 圓柱 | 同 `object` |
| `surface/gate` | 人為關卡：核准、審查、放行 | 雙線框 | 同 `object` |
| `surface/external` | 界外系統，不受我方控制 | 虛線框 `6 4` **＋照常填色** | `infra` 系 |
| `state/planned` | 規劃中、尚未建置 | 虛線框 `6 4` **＋不填色** | 該類別的 `line` |
| `state/deprecated` | 退場中、不在本次範圍 | 斜線紋 ＋ 中性色 | `infra` 系 |
| `surface/emphasis` | 這一頁在講的那個框 | 實心偏移陰影 | `highlight` |

`object`／`region`／`annotation` 三者必須在**一眼之內**視覺可辨，
且任一者不得承擔兩種意義。讀者第一屏學會這套詞彙，之後全靠它導航。

### 狀態角色的通道分配

對照表在 `docs/style-reference.html` 的「狀態」一節
（`python scripts/render_reference.py` 重生）。
**改動任何狀態角色後，按頁上的「灰階檢視」再看一次**——這一節存在的目的
就是防止「只降飽和」那個錯誤，而那個錯誤在彩色下看起來完全正常。


`external`、`planned`、`deprecated` 三者容易撞在一起，因為直覺上都想用虛線。
但它們**編碼不同的軸**——所有權、時間、生命週期——一個框可能同時是
「界外的」又是「規劃中的」，所以不能共用通道：

| | 邊框 | 填色 | 灰階下靠什麼分辨 |
|---|---|---|---|
| 一般 | 實線 | 有 | — |
| `external` | 虛線 | **有** | 邊框樣式 |
| `planned` | 虛線 | **無** | 邊框樣式 ＋ 有無填色 |
| `deprecated` | 實線 | 斜線紋 | 紋理 |

**`deprecated` 不能只靠降飽和。** 飽和度在灰階下完全消失，
退場中的元件會變得跟正常元件一模一樣。斜線紋才是那個活得下來的通道。

**`blueprint` 筆調有例外**：`fill: outline` 讓所有東西都沒有填色，
`planned` 的「不填色」失去區別力。該筆調下 `planned` 改用**斜線紋加虛線框**，
與 `deprecated` 的實線＋斜線紋仍然分得開。

## highlight — 螢光筆

單一值，兩種用法，都是**強調而非結構**：

- **`text/highlight`**：文字下方的色塊畫記。做成**底線式**（覆蓋文字下緣約
  0.4em）而非整行反白——整行反白會讓那段文字變成一個「表面」，
  與卡片語彙撞在一起。
- **`surface/emphasis`**：卡片後方偏移的實心色塊（`depth: solid`）。
  PPT 逐頁強調同一張架構圖的不同部分時用這個，比改變卡片本身的顏色安全，
  因為類別色是承諾、不能為了強調而挪用。

三個限制：

0. **色相必須離每個類別色 ≥30°。** 螢光筆若跟某個類別同色系，
   畫記讀起來會變成「這屬於第 N 類」而不是「這裡被標了」。
   黃色是直覺反應，但**任何有暖色類別的主題都不能用黃**——
   現有主題都曾撞過這一關，最嚴重的一組差 0°。
   `derive.py` 會擋。

1. **`ink-strong` 對它必須 ≥4.5:1**，因為文字會壓在上面。
2. **對畫布只要求 1.25:1**，遠低於圖形元素慣例的 3:1。
   螢光筆是**染色不是對比**——真實的螢光筆對白紙只有 1.1–1.3:1。
   門檻訂太高會逼出鉻黃，那會蓋過它本來要標示的文字。
   安全性要求在**壓在它上面的字**（4.5:1），不在它對紙面的對比。

**螢光筆不共用同一個值，但也不完全跟隨主題。**

- **色相固定在 H52**（黃）。不要用 H40–46 的琥珀色相：
  **暖色相加低飽和會變米褐**，看起來像泛黃的紙而不是畫記。
- **飽和度有下限 0.70**，上限 0.85。低飽和主題不該把螢光筆一起拉淡——
  螢光筆是外來物，那正是它的語意；淡到與紙同調就失去作用。
  高飽和主題則往上跟隨，否則會消失在它自己的濃卡片旁邊。
- **明度**解到對畫布 1.33:1。

單色主題（`blueprint-mono`）是唯一例外：用**同色相的淺階**（H205），
飽和度下限降到 0.55。它的畫記本來就該看起來像用同一支筆淡淡掃過，
而不是換了一支筆。

**一頁 ≤2 處。** 螢光筆的作用來自稀缺；畫滿三處以上等於沒畫。
它也**不得與 `accent` 同時用在同一個元素上**——兩個強調疊加會互相抵銷。

## 線條角色

| 角色 | 意義 | 線型 | 顏色 |
|---|---|---|---|
| `line/flow` | 主資料流、執行順序 | 實線 | `connector` |
| `line/control` | 控制流、非同步、回饋 | 虛線 `6 4` | `connector` |
| `line/reference` | 邏輯關聯、參照，**非執行** | 長虛線 `10 5` | `connector` @ 60% |
| `line/optional` | 條件性連線，可能不發生 | 點劃線 `8 3 2 3` | `connector` @ 70% |
| `line/leader` | 註解引線 | **點線 `2 3`** | `ink-muted` @ 70% |
| `line/boundary` | 包含邊界 | 點線 `2 3` | `ink-muted` @ 70% |

> 表中的陣列是 `console`（線寬 1.5px）的值。**虛線長度隨筆調的線寬縮放**，
> 換算表在 `layer-pen.md`。語意固定，節奏隨筆調走。

**`line/control` 與 `line/leader` 必須用不同線型。** 兩者都是「非實線」，
但一個是機制的一部分（控制流真的存在於系統裡），一個不是（引線只是把說明指向某處）。
共用同一個 dash pattern 時，讀者無法判斷那條線是不是系統行為。

分法是：**機制用 dash，非機制用 dot。** `surface/annotation` 與 `line/boundary`
同屬非機制，所以共用點線；`line/flow`、`line/control`、`line/reference`、
`line/optional` 都在描述系統，所以都是實線或 dash 家族。

`line/optional` 用**點劃線**而非另一種長度的虛線：`6 4` 與 `10 5` 已被佔用，
再加第三種純虛線時三者在縮圖下分不出來。點劃線的節奏差異夠明顯。

## 角色不足時

素材出現無法歸類的元素時**停下來問**，不要硬塞進最接近的角色。
硬塞的後果是靜默的——圖看起來正常，但說了一件素材沒說的事。

新增角色是可以的，但新角色必須在兩層都有定義，且與既有角色**視覺可辨**。
只加顏色不加形狀的新角色會在灰階下消失。
