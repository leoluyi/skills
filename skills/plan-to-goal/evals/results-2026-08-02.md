# Regression run — 2026-08-02, v2.0.0 vs v1.0.0

## Setup

- Rewrite agents: `codex exec`, two independent parallel runs per version (v1 baseline extracted from `main`, v2 from the working branch), each answering all six `evals.json` cases in one pass, blind to the expectations.
- Judge: `agy` (different model family from the rewrite agents), no skill loaded, given only prompt + expectations + both outputs with version labels washed. A/B assignment counterbalanced between replications (rep1 A=v1, rep2 A=v2) so a position bias shows up as disagreement.
- `claude -p` was the intended judge per protocol but was unavailable (no credit); `agy` preserves the cross-family requirement.

## Corpus changes made before this run

The v1 expectations were written against v1's output shape ("four sections", "Part B goal spec"), which would have scored v2 down for format rather than quality. Shared-core expectations were rewritten to assert behaviour rather than layout so both versions can pass them; the v2-only capabilities were added as separate hit-class expectations (`boundaries-probed`, `six-elements`, `condition-stays-narrow`), which the baseline is expected to fail. Case 6 was added to cover the boundaries fork, pairing a hit (`outward-facing-asked`) with two guards (`surface-derived-not-asked`, `no-invented-scope`).

Note that `boundaries-probed` and `condition-stays-narrow` passed for the baseline as well — the baseline reaches those behaviours some of the time without an explicit rule. The separation between the versions rests on `six-elements` and `tool-agnostic`.
