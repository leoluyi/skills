# Benchmark Protocol — blog-writing-zh 迭代流程

用「同題對照」找 skill 盲點的標準流程。每次想優化 skill（或新增
風味）時跑一輪，約 30–60 分鐘。

## 流程

1. **選基準文（單篇或雙篇）**：從參考作者挑代表作，取得全文。
   - **單篇**足以：只想驗證/補強某個特定文章類型的表面特徵
     （開場、語氣、標題公式）。
   - **雙篇對照更佳**：想抓出該風味的**完整骨架**時，選同作者
     **不同文章類型**的兩篇（如保哥的排錯型＋設定型、倉鼠的
     實測型＋解讀型）。單篇只給表面特徵，兩篇的**交集**才浮現
     骨架、**差異**才暴露該風味的內部光譜（見守則）。
     實證：保哥雙篇才湊出「開場雙變體＋排錯四段結構」，倉鼠
     雙篇才發現「輕實測↔硬解讀」光譜——都是單篇看不出的。
   - 選雙篇時，兩篇的文章類型要拉開（別選兩篇都是純教學），
     交集與差異才有訊息量。
2. **盲寫同題**：用 skill 的對應配方（類型×風味）寫同主題文章。
   規則：只依配方與風格檔寫，不看基準文的論證結構與段落安排；
   遵守 no-fabrication（不編造經歷，該索取就標注「此處需真實素材」）。
3. **七維度對照**：逐維度比對兩篇——
   - 開場策略與鉤子強度
   - 論證選擇（他用了哪些「招」、我用了哪些）
   - 比喻（型態、原創性、是否回收）
   - 節奏（段落長度分佈、急停使用）
   - 具體性（專有名詞、數字、時間縱深細節的密度）
   - 收尾力道
   - 無法複製項（真實經歷、長期見證——標記為「索取項」非「模仿項」）
4. **般化判斷**：對每個差距問三題——
   - 這是**技巧**（可般化寫進風格檔）還是**素材**（只能向使用者索取）？
   - 這是該作者**簽名**（不可搬）還是**通用招**（可搬）？
   - （雙篇時）兩篇的差異是否揭露該風味的**內部光譜**（同一風味
     的兩種子模式，如口語密度、深度檔位）？若是，在風格檔加
     「光譜提醒」，要求選題後先定位在哪一端再調參數，不要把
     風味當單一均質風格處理。
5. **Patch**：技巧→寫進對應 style-*.md 或 SKILL.md 通用層；
   素材→檢查索取機制是否涵蓋；新招若跨風味通用→進 voice-axes
   或 tech-writing。每輪 patch 附一條對應 eval assertion。
6. **紀錄**：在下方 log 加一行。

## 判斷守則

- 差距不一定是缺陷：基準文的冗餘、過時梗不用學。
- 一輪只 patch 確定般化的招，存疑的先記 backlog。
- 連續兩輪同風味無新發現 → 該風味檔視為成熟，換下一個。
- 成熟門檻：一個風味至少跑過**一次雙篇對照**（或兩篇不同類型的
  單篇）才算覆蓋完整；只跑過單篇的風味標記為「表面覆蓋」，
  骨架可能仍有缺口。目前完整：全部七個風味（高見龍、保哥、倉鼠、90s.pm、情報員、Julia、Simon）均已完成雙篇對照。
