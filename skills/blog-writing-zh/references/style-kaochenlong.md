# 高見龍（kaochenlong.com）— 對話幽默型

**定位**：像資深朋友聊天一樣談觀念與成長，幽默包裹認真的論證。
適用：觀念倡議、職涯成長、學習方法、軟性技術題。

## 結構骨架

1. **讀者內心 OS 開場**：條列讀者會有的抗拒反應
   （「我文筆很爛。」「我沒什麼東西好寫的。」「我那麼菜，寫出來會被笑。」）
   然後接「這些想法其實很正常。」——先接住情緒再論證。
2. 主論證：每節一個理由，H2 標題本身就有態度（「舒適圈超爽的！」
   「真的懂了嗎？」「免費的審查」）
3. 反駁擊破段：預判藉口逐一擊破（H4 引號小標：「我的文筆不好」
   「我沒時間。」），每個藉口先同理再拆解。
4. 收尾：行動呼籲＋留鉤子預告下集。

## 語感特徵

- **先立後破**：先陳述常見說法，再用口語推翻——
  「長輩都跟我們說要跳出舒適圈…但說實話，待在舒適圈超爽的，幹嘛跳出來。」
- **與讀者直接對話**：「你說用 AI 生成很快？是啦，不過…」
  「還是你覺得我這篇文章有什麼特別厲害的地方嗎？沒有吧？」
- **自嘲式可信度**：「我原本可能對 Git 就只有 60 分的勉強及格程度」——
  用自貶換取論點可信度。
- **具體場景故事**：「凌晨三點因為搞錯 rebase 把同事的 code 蓋掉，
  被罵到臭頭」——時間＋動作＋後果，三元素俱全才真實。
- **反高潮收句**：拒絕勵志腔——「我不會說什麼『成就感讓人上癮』這種話。
  我只會想：『終於寫完了，可以去打我的魔物獵人了。』」
- **meta 幽默**：「就算是老生常談的主題，例如這一篇文章就是
  （你有發現嗎？）」
- 口語詞彙：「摸摸鼻子」「支支吾吾」「嘿嘿」「該死的 bug」「滑脆、滑 IG」。
- 括號補充當第二聲道：（吧？）（更精準的講是動鍵盤）。
- **劇情式比喻**（技術文的招牌）：比喻不是一句類比而是一段有角色有
  情節的小故事——講 Skills 用「小吃店廚師收到台南小吃完全手冊」，
  還混入武俠梗（骨骼精奇、練武奇才、武功秘笈）。故事講完回收：
  「Skills 就是這本武功秘笈。」
- **「翻成白話文就是…」過渡句**：官方定義之後必接一句人話版。
- **輕描淡寫評價**：「這滿好的」——重大優點用淡語氣講，反而有說服力。
- **演進敘事框架**：技術文用「三階段」講脈絡（一問一答 → Function
  Calling → Skills），讓新功能有歷史座標。

## 技術文專屬招式（補充樣本：Claude Code Skills 一文）

- **「翻成白話文就是」句式**：官方定義後立刻接一句人話版。
- **長比喻教學**：用完整生活故事教抽象概念（小吃店廚師收到「台南小吃
  完全手冊」武功秘笈 → Skills 是技能包），比喻裡藏武俠梗（骨骼精奇、
  練武奇才）增加娛樂性，但比喻的對應關係嚴格成立。
- **演進三階段敘事**：「從一問一答 → Function Calling → Skills」，
  用歷史脈絡定位新事物的意義。
- **對仗收束比較**：「一個是腦袋裡的知識，一個是手上的工具。」——
  兩個易混概念的比較永遠收在一句對仗。
- **輕判斷語**：「這滿好的」「滿有意思的」——技術文的立場句比觀念文
  收斂，但仍然有。

- **門檻拆除（承重論證）**：把目標行為重新定義為讀者已在做的事——
  「我們每天其實都在寫東西：commit message、PR 說明、在 issue 裡
  解釋 bug」。不是勸讀者開始新行為，是指出他早就在做了。
  這招要當主論證用，不是一句帶過。
- **Meta 自證**：用正在讀的這篇文章當論據——「還是你覺得我這篇
  文章有什麼特別厲害的地方嗎？沒有吧？但對剛想寫的人或多或少
  能幫到。」
- **引用存疑標記**：出處不確定就誠實標注——「愛因斯坦*可能*曾
  講過」。誠實與幽默一次達成。
- **在地專有名詞**：PTT、Threads、天瓏書局、公司的 Discord/Teams
  ——在地感來自具體名詞密度，不來自語氣詞。
- **建議掛書**：關鍵建議引一本書背書（《Bird by Bird》的 Shitty
  First Drafts），不讓建議懸空。
- **系列文拆法**：觀點題常拆「上＝為什麼／下＝怎麼做＋題目哪裡來」，
  上篇尾留鉤子。

- **猜測讀者狀態的體貼**：「我猜可能有些人連 Start 節點用都沒
  用過」——主動降級變更的嚴重感，減少讀者焦慮。
- **服務姿態開場**（教學文）：「來來來，我幫大家做好功課了」——
  把文章定位成替讀者省時間的服務。
- **受災報告**（索取項）：作者自己被變更影響的具體案例（「我的
  備份工作流剛好用到這兩個節點」）——教學文的信任加成，
  需向使用者索取真實案例，不可虛構。

## 標題公式

- 祈使＋稱呼：「寫作吧，菜鳥工程師！」
- 帶態度的問句：「給 AI 超能力？Superpowers 的設計與取捨」
- 比喻宣告：「Claude Code Skills：讓 AI 變身專業工匠」

## 禁忌

- 幽默必須服務論證；純搞笑段落刪掉。
- 自嘲不可貶到失去專業可信度——貶的是過去的自己，秀的是成長路徑。
- 反高潮句一篇 1–2 次；他本人的簽名句（魔物獵人等）不可照抄，
  要換成使用者自己的生活元素。
