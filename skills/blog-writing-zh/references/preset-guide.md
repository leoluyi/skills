# Preset Guide — 依主題與對象推薦配方

當使用者只給主題（或素材）沒指定風格時，走本檔的推薦流程，
產出一組「類型×風味」建議＋一句理由，再以單選讓使用者確認
（建議選項：推薦組合／第二候選／看全部類型）。

## 推薦邏輯：兩個問題決定類型

主題領域（AI／商業／工具…）**不決定**文章類型；決定類型的是：

**Q1 讀者讀完要做什麼？**（從素材或使用者敘述推斷，推不出來才問）

| 讀完要… | 類型 |
|---|---|
| 照著做出來 | 教學實作型 |
| 搞懂一個東西是什麼／跟 X 差在哪 | 概念導讀型 |
| 理解原理或一篇深度內容 | 深度解讀型 |
| 快速獲得一個可用的小發現 | 實測筆記型 |
| 被說服、改變作法 | 觀點倡議型 |
| 做出買不買／用不用的決定 | 拆解評測型 |
| 學會一套可複用的分析方法 | 分析框架型 |

**Q2 讀者跟主題的關係？**（決定風味與濃度微調）

| 關係 | 微調 |
|---|---|
| 害怕它／覺得自己學不會 | Julia 風味優先（先卸恐懼再教）；E2 不超過 L2 |
| 用過但一知半解、常踩坑 | 保哥（糾錯式）或 Julia（困惑具名化） |
| 沒聽過、需要被勾起興趣 | 倉鼠（場景鉤子）或高見龍（劇情比喻） |
| 專家同儕、時間寶貴 | Simon（TL;DR＋證據鏈）；砍鋪陳 |
| 正在被行銷話術轟炸 | 情報員（三欄拆解＋誠實反轉） |

## 對象校準：三個變因

**1. 技術程度 → E6 術語處理**
- 非技術（主管、PM、一般讀者）：白話翻譯句＋劇情式比喻；英文術語
  減量，出現必附中文；避免指令區塊當主角。
- 半技術（跨域工程師、資深使用者）：三層法（預設）。
- 同溫層專家：術語直用不解釋；解釋基礎概念反而顯得不尊重讀者。

**2. 讀者與作者的關係 → E2 人設濃度**
- 陌生大眾／SEO 流量：L1–L2（信任未建立，人設先收）。
- 訂閱讀者／社群熟客：L2–L3（人設是他們來的原因）。
- 企業內部／客戶：L1，觀點放開頭結尾，正文專業。

**3. 發布場景 → E8 標題與長度**
- SEO／搜尋流量：如何型、解密型標題；結構完整可跳讀。
- 電子報：鉤子型、宣言型標題；導讀段必備。
- 社群轉發：二元對立問句、釣魚反轉（內文必須誠實兌現）。

## 情境速查表（範例，非窮舉）

| 情境 | 推薦 | 理由一句話 |
|---|---|---|
| 教非技術 PM 理解 RAG | 概念導讀型×高見龍 | 需要劇情比喻＋定位澄清，不需要指令 |
| 寫給怕 git 的設計師 | 概念導讀型×Julia | 先卸恐懼，困惑歸因於工具 |
| 團隊內部 K8s 除錯手冊 | 教學實作型×保哥（L1） | 可重現優先，內部文件人設收斂 |
| 今天發現的 CLI 小技巧 | 實測筆記型×Simon | 小而完整，當天發 |
| 解讀 Anthropic 新論文給訂閱者 | 深度解讀型×倉鼠 | 譯寫雙模式＋導讀視角 |
| 說服工程師開始寫部落格 | 觀點倡議型×高見龍 | 藉口擊破天生為此而生 |
| 新 AI 訂閱方案值不值得買 | 拆解評測型×情報員 | 三欄拆解＋替讀者省錢立場 |
| 教讀者一套評估工具的方法 | 分析框架型×90s.pm | 零件化＋自建比喻系統可複用 |
| 商業／投資主題但讀者是散戶新手 | 分析框架型×90s.pm，E2 降 L2、比喻加生活類比 | 框架不變，門檻調低 |
| 向主管提案導入新工具 | 概念導讀型×無風味（L1）＋判斷標準收尾 | 對內說服重邏輯輕人設 |

## 推薦話術格式

推薦時一句話講清楚「因為讀者是誰＋要做什麼」，例如：
「讀者是還沒用過 agent 的後端工程師，讀完要能自己跑起來——
建議**教學實作型×Simon**：可重現四要素＋完整指令證據鏈。
或者你想先勾起他們興趣，可改**概念導讀型×高見龍**。要用哪個？」

不要列七個類型讓使用者自己讀表格；推薦 1 個主案＋最多 1 個備案。

## 特殊情況

- 一篇文想同時服務新手與專家：預設拆兩篇（建議使用者）；堅持一篇
  則主體照新手層級寫，專家內容收進「進階」小節或延伸閱讀。
- 素材是 Obsidian 筆記：先照 rewrite-playbook 提煉單一主張，
  再依主張的性質（教做法？教概念？下判斷？）走 Q1。
- 使用者的既往配方紀錄存在且主題相近：優先沿用，只確認差異。
