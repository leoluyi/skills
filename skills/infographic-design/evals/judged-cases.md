# Judged Cases — 帶 ground truth 的重跑素材

質性評估用的案例庫(原則見 `../design-notes.md` 的評測一節)。每一筆的判定都是使用者
**在該次執行當下**表達的,不是事後補的評語 —— 這正是自產 scenario 缺的
東西。

改動核心規則(step 1、章節序、密度、gate 嚴重度)之後,拿這些原始素材
重跑,看新版本是否仍能產出被偏好的性質。設計品質不適合硬塞成
expectation,這裡是它該被評的地方。

判定只記錄使用者實際說過的;沒有明確判定的產出不列入,即使它通過了 gate。

---

## C-01 · HTTPS handshake:原版 vs reference 版

| 欄位 | 內容 |
|---|---|
| 原始素材 | 「畫一張 HTTPS handshake 的圖」 |
| 使用者判定 | **原版較好** |
| 判定關鍵 | 不是留白,是**資訊密度與邏輯關係** |
| 蒸餾出的規則 | payload 放在箭頭上;誰做這件事由位置決定,不由 caption 說;推導畫成 data-flow 而非文字宣稱 |
| 重跑要問 | 新版本產出的圖,讀者能否只憑圖驗證推導,而不必讀 caption? |

當時 deterministic gate 全綠,但圖把機制核心關係稀釋成了 caption ——
這是「全綠不等於好」的第一個實例。

## C-02 · Kubernetes 學習回顧:使用者原版 vs skill 重建版

| 欄位 | 內容 |
|---|---|
| 原始素材 | `从 Envoy 迁移到 Traefik` 對話中的 `/learn` 教學段(七課) |
| 使用者判定(三項) | (a) 原版**違反**章節序=授課序,要升為鐵律;(b) **強烈偏好原版的視覺工程**(動畫流線、symbol 圖示、節點剖面);(c) 期望 `/infographic-design 學習總結成一張圖` 直接產出同內容同格式,不需再下 prompt |
| 蒸餾出的規則 | 刪除 `Typical PART skeleton`(埋著旅程序範本);章節序改以概念相依鏈正面表述 + Fold-don't-transcribe;視覺工程升為通用規定(地標觸發、表面詞彙、多 flow dash、頁框) |
| 重跑要問 | 章節是否照授課序並以「第 N 課」命名?圖示、動畫、卡片/色帶/註記三件式是否**未經要求就出現**? |

重建版當時輸在視覺工程,正因為那些東西那時還是選配。

## C-03 · skill anatomy:官方 frontend-design 對照

| 欄位 | 內容 |
|---|---|
| 原始素材 | 「視覺化產出一張圖:解釋 infographic design skill 的能力範圍、組成、workflow」 |
| 對照組 | 只載入官方 `frontend-design`,不用本 skill 任何機制 |
| 發現(負面向,不受污染影響) | 本 skill **完全沒有文案指引**,而資訊圖表的表面大半是文字 |
| 蒸餾出的規則 | 匯入 `references/words.md` |
| 重跑要問 | 再跑一次 Layer 1,對照組還有什麼是我們沒有的? |

這個缺口內部 review 兩輪都沒發現,因為它是「缺什麼」而非「哪裡寫錯」。

## 加新案例的條件

四項都滿足才加:

1. 素材是真實請求或真實對話,不是為了測而編的。
2. 使用者的判定在該次執行當下就表達了。
3. 判定**轉折在什麼上**寫得出來(「比較好」不算,要說出差在哪)。
4. 從判定確實蒸餾出了一條規則,而且指得出它現在住在哪個檔案。
