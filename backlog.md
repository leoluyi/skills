- [ ] **avoid-ai-writing-zh: refactor to simplify while raising effect, backed by current skill-authoring guidance.** Noted 2026-07-28. Three linked strands; do them in order (refactor → evals → tooling) or the eval rewrite measures a moving target.

  **(a) Refactor: cut rules, keep the priors the model doesn't have.** Primary reference — [The new rules of context engineering for Claude 5 generation models](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models). Its thesis reframes this whole item: Anthropic removed **over 80% of Claude Code's own system prompt** for Claude 5 with no performance loss, because the newer models need far less explicit instruction. Rules → judgment ("write code that reads like the surrounding code" replacing "never write multi-paragraph docstrings"); repetition → conciseness; upfront loading → progressive disclosure. Secondary, for mechanics only: Anthropic's [skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) and Matt Pocock's `writing-great-skills` (local: `~/.agents/skills/writing-great-skills/` + `GLOSSARY.md`).
    - **The real thesis: most of this skill is a rule list Claude 5 no longer needs.** The body is two flat catalogs of ~50 `###` micro-categories each — English AI-isms (L147–402) and 繁中 AI-isms (L402–760). The English catalog is the prime suspect: "delve", "it's not just X, it's Y", em-dash abuse, hedge stacking are strong priors the model already holds, and spelling out 50 of them is the exact "explicit constraints" pattern the post says to retire. The load-bearing content is what the model *lacks* priors for — the 繁中/台灣 layer (translation-ese, 陸味, slogan lines) and the structure-signals gate (naming what's *absent*: no stance, no concrete detail, no self-made metaphor). Test the strong version: cut the English catalog to a short judgment-shaped statement plus the existing `references/english-phrase-rules.md` pointer, and see whether evals move. If they don't, that's ~250 lines gone for free.
    - **Length is a symptom, not the target.** `SKILL.md` is 965 lines. This is regression, not new growth: 488f51a extracted the English rules (935→565), d7347fe partially undid it (only the phrase lookup tables stayed in `references/` — `english-phrase-rules.md` 166 lines, `zh-phrase-rules.md` 81), then five commits on 07-19/20 stacked more on. Pocock's name for this is **sediment**. Re-extracting is the weak fix; deleting is the strong one — and the branch structure (language routing already splits en / zh-tw / mixed) makes disclosure the right home for whatever survives the cut.
    - **Negation.** 130 negation tokens (`never` / `don't` / `avoid` / `not`). Same defect already logged against infographic-design, and the same direction the post points: state the target behaviour, trust judgment. Note the awkward bit — this skill's *subject matter* is a list of things not to write, so full inversion may not be reachable; aim at the instruction layer, not the pattern catalog.
    - **Leading words.** Look for restatements that collapse into one pretrained word — the move that turned infographic-design's `base position` into `home`. Severity tiers and the structure-signals gate are the likeliest candidates. This is compression, so it serves the cut rather than fighting it.
    - **Completion criteria — apply with restraint.** Adding a checkable **Done when** to each mode helps "iterate to convergence" stop being self-judged, but it cuts against "trust judgment". Add only where a mode actually terminates early in practice; don't scaffold all four on principle.
    Constraint: measured bar, not a shorter-is-better bar — the refactor must beat the current version on `evals/evals.json`. Given the 80%-cut precedent, run it as an ablation (drop a block, re-run, keep the cut if the score holds) rather than a single rewrite.

Each one pre-labels exactly the judgment under test — the run measures compliance with the hint, not detection. Rewrite them as bare text with the labels moved into `expectations` only, then re-baseline (every pass rate recorded against these three is void). Gaps to fill after: the two untriaged fails from the 07-19 resweep (id 3 en/rewrite, id 10 structure-signals), plus false-positive cases on voice-neutral genres.

  **(c) New tool: a mark-and-iterate loop for example articles.** Want a low-friction way to point at a sentence in a sample article and say "this one is wrong / this one is fine", accumulating a judged corpus that drives the next iteration — instead of hand-editing JSON. Note there is already `evals/judged-cases.md` and `evals/adversarial-eval-protocol.md`; decide whether this is a script over that format (`tools/`-level, like `run-eval`) or a skill. Design question to settle first: what the marked-up input looks like (inline markers in a Markdown file vs a side-car JSON of line/span + verdict) — the format determines whether the loop can be scripted at all. Should generalize beyond this one skill; `blog-writing-zh` and `avoid-china-writing` have the same need. The Claude-5 post also argues **simple specs → rich references**: rubrics and test suites beat prose descriptions as executable references. That makes the judged corpus this tool produces more valuable than the prose rules it would replace — it's the artifact strand (a) cuts *toward*, not just a testing convenience.
